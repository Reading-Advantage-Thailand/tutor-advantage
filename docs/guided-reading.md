# อ่านไปกับรีดี้

## ปรับเป็นรีดี้นำการเรียนทั้งหมด

หน้าอ่านเป็นเนื้อหาอ่านอย่างเดียว ไม่มีปุ่มเลือกประโยค เปลี่ยนศัพท์ อ่านซ้ำ เปิด/ปิดบทความ หรือก่อนหน้า/ถัดไป นักเรียนตอบตกลง ปฏิเสธ ขออ่านซ้ำ ขอคำใบ้ หรือขอกลับไปคุยด้วยเสียง รีดี้เลือกและสั่งเปลี่ยนหน้าจอผ่าน tool เท่านั้น เมื่อเปิดบทความจะเลือกและไฮไลต์ประโยคแรกพร้อมเริ่มพาอ่าน ไม่ถามให้นักเรียนเลือกส่วนที่จะเรียน

ยังคงปุ่มเริ่มสนทนา ปิด/เปิดไมค์ และจบการฝึก ส่วน Dev จำลองการกระทำได้โดยไม่ใช้เสียง รายละเอียดด้านล่างเรื่องปุ่มควบคุมการอ่านเป็น flow รุ่นก่อนและถูกแทนที่ด้วยการตอบเสียงตามย่อหน้านี้

## ประสบการณ์นักเรียน

1. นักเรียนตอบไม่ได้: รีดี้ให้คำใบ้สั้น ๆ หนึ่งครั้ง ไม่ตัดสินว่าตอบผิด
2. ยังจำไม่ได้: รีดี้เรียก `guide_reading(offer)` และถามว่าเปิดบทความอ่านด้วยกันไหม หน้าจอมีปุ่มตกลง/คุยต่อ
3. นักเรียนตกลงด้วยเสียงหรือปุ่ม: เปิดบทความเต็ม ย่อรีดี้ไปขวาบน ใช้บทความที่ตรวจชื่อแล้วว่าตรงกับเล่มนี้เท่านั้น
4. อ่านทีละส่วน: รีดี้เลือกข้อความตรงกับต้นฉบับผ่าน `focus` หน้าจอไฮไลต์ประโยคและเลื่อนไปยังจุดนั้น จากนั้นออกเสียงช้า ๆ ให้คำใบ้ไทย และรอนักเรียนลองอ่าน นักเรียนเลือกประโยคเองหรือใช้ปุ่มก่อนหน้า/ถัดไปได้
5. ฝึกศัพท์: `word` เลือกเฉพาะศัพท์ในบท เปิดการ์ดคำ/ความหมายด้วยแอนิเมชัน รีดี้อ่านหนึ่งครั้งแล้วชวนอ่านตาม มีปุ่มฟังอีกครั้ง
6. กลับไปคุย: ปุ่มกากบาทหรือบอกรีดี้ให้กลับไปสนทนา ปิดหน้าอ่านโดยไม่จบ call

เปิดหน้าอ่านก่อนเริ่ม call ได้เพื่อดูเนื้อหา แต่เสียงและการประเมินการอ่านต้องเริ่ม call ก่อน เวลาเชื่อมต่อยังหักตามสิทธิ์เดิม การเปิดบทความก่อนเริ่ม call ไม่ใช้เวลาเสียง

## การเชื่อมต่อ

- เพิ่ม Realtime function `guide_reading`: action เป็น offer/open/focus/word/close และ quote เป็นข้อความจากบท
- เว็บรับเฉพาะ function ใน `response.done` ที่ completed ป้องกันผลจาก response ที่ถูกยกเลิก ใช้ call ID กันซ้ำ
- เว็บตรวจ quote กับบทความ/คลังศัพท์ก่อนอัปเดต UI ส่ง function output success/failure กลับ แล้วขอเสียงสอนสั้นหนึ่งครั้งโดยปิด tool เพื่อป้องกันการเรียกวน
- การยินยอมด้วยเสียงตีความโดยโมเดลตามคำสั่งให้ถามและรอ ไม่ใช้ regex ตรวจคำว่า “ได้” ซึ่งอาจมีความหมายคลุมเครือ
- Strict Guard ฝั่ง server ยังคงตรวจเสียงนักเรียนก่อนสร้างคำตอบ ส่วนปุ่มส่งเฉพาะ intent ที่กำหนดและข้อความต้นฉบับ ไม่มีช่องข้อความอิสระใหม่
- เมื่อรีดี้กำลังพูด/สร้างคำตอบ ปุ่มเลือกบทเรียนแจ้งให้รอจนจบก่อน เพื่อไม่สร้าง response ซ้อน นักเรียนยังพูดแทรกได้ตามระบบเสียงเดิม
- ไฮไลต์ระดับประโยค/คำที่เลือก ไม่ใช่ karaoke ที่จับเวลาแต่ละพยางค์
- ไม่มีการบันทึก transcript หรือเสียงเพิ่ม ใช้ context และ session เดิม

## การตรวจและ manual acceptance

- อัตโนมัติ: ข้อความบทความหลังแบ่งประโยคต้องต่อกลับได้ครบตรงต้นฉบับ; tests Strict Guard เดิม; TypeScript และ lint
- UI local: 390×844 และ 360×640 เปิดอ่าน เลือกศัพท์ ไฮไลต์ กลับหน้าคุย ปุ่มเริ่มคุยอยู่ในจอ
- ต้องทดสอบเสียงจริงกับบัญชี provider: พูดว่าจำไม่ได้สองรอบ → รับคำชวน → ตอบตกลง → ขออ่านประโยค → อ่านตาม → ขอศัพท์ → ขอพูดซ้ำ → กลับไปคุย
- ทดสอบปฏิเสธคำชวน, พูดแทรกระหว่างออกเสียง, หมดเวลาในหน้าอ่าน, network disconnect และคำขอออกนอกบท
- การออกเสียงและความแม่นยำในการชวน/เลือกข้อความยังต้องตรวจด้วยเสียงจริง ไม่สามารถยืนยันจากการทดสอบ UI อย่างเดียว

อ้างอิงรูปแบบ function output และ response lifecycle: https://developers.openai.com/api/docs/guides/realtime-conversations
